## Included with your account

Servers your account is granted connect when you sign in and at the start of every session. Nothing to configure. A server granted later appears the next time you start `hum`.

Every account has `docs`: Hum's own documentation as a tool server. Ask Hum what it can do or how a setting works and it reads the page before answering. For a reader outside a session the same pages are an index at [/llms.txt](/llms.txt) and markdown at `/docs/<page>.md`.

```
/mcp [name]       # every server: pick one to show its tools, reconnect it, sign in or sign out
/tools            # every tool the model has, and the sandbox it runs in
```

## Your own

```
hum mcp add kennet https://metaphi-ai--kennet-harness-mcp-web.modal.run/mcp/
hum mcp login kennet                       # the browser opens; sign in with GitHub to work on a repository
hum mcp add db -- npx db-mcp --readonly    # a server started here
hum mcp add team https://.../mcp --scope project   # for everyone in this repository (.hum/config.toml)
```

A server that answers 401 names where to sign in; `hum mcp login` takes you there once and keeps what it issued. A session mounts a server you have not signed in to and prints the link the first time it is needed.

The same, written by hand:

```toml
# ~/.hum/config.toml
[[mcp]]
name = "jira"
url = "https://.../mcp"

[[mcp]]
name = "db"
command = "npx"
args = ["db-mcp", "--readonly"]
timeout_s = 900              # seconds one call may take; default 900
```

Each `[[mcp]]` table mounts into every session. `/mcp` shows whether it mounted, and signs in, reconnects or signs out from there.

| Key | Description |
| --- | --- |
| `name` | What the server's tools are called by (`name__tool`) |
| `url` | Streamable-HTTP address |
| `command`, `args` | Start the server here instead |
| `headers` | Sent with every HTTP request |
| `env` | Variables a server started here is given |
| `timeout_s` | Seconds one call may take before it fails; default 900 |

## What a server gets

- A server that asks for a file or a directory as base64 gets it from Hum. The model names a path under the working directory; Hum packs and encodes it.
- A server runs with the reach of its own process. The sandbox does not extend to it.
- An image a server returns (a screenshot, a rendered page) reaches the model as a picture and stays with the session, like one you paste.
- Credential-like variables (`*KEY*`, `*PASSWORD*`, `*SECRET*`, `*TOKEN*`, `*CREDENTIAL*`, `HUM_*`) are stripped from a server's environment. Pass the ones it needs:

```toml
[sandbox]
env_pass = ["JIRA_TOKEN"]
```
