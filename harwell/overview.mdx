description: "Harwell runs mainframe batch and online code off the mainframe, and answers every run with one report of exactly what happened."

Harwell takes the COBOL, JCL, copybooks, BMS maps and Db2 DDL a z/OS shop already has, in the shape it already has them, and runs them. Two kinds of work run:

| | What runs | What you read back |
| --- | --- | --- |
| Batch | A JCL job: its steps, the programs and utilities they call, the data sets they read and write, Db2 under the step | Each job and step, its return code or abend, what it printed, the data sets and tables it left |
| Online | A CICS transaction in a region: its programs, BMS screens, files, queues and Db2 inside the task | Each screen the task sent, painted as the terminal shows it, each unit of work, each abend |

Db2, VSAM and GDGs are shared data under both.

## What you get

- One JSON report per run: each job, each step, its return code, what it printed, and every place the run did something the mainframe would not have.
- A fidelity verdict on every run: `clean`, or `degraded` with each cause named.
- Refusals by name. A construct Harwell cannot answer is refused with the reason, never skipped.
- Repeatable runs. The run clock is the whole system clock, so a run repeats byte for byte.
- Expected end states. State the data sets, tables or screens a run must leave, and the same run carries a verdict.

## What it is not

Harwell is a toolchain, not a grader. It runs code and reports. Whether a change is correct is decided by whatever reads the report: a test, a CI job, a person.

It is not a conformance claim. No conformance suite for this platform exists, from anybody. What Harwell does differently from the mainframe, where known, is listed in [Known limits](/harwell/known-limits).

## Who it is for

Mainframe teams and engineering leaders at banks and insurers running COBOL, CICS and Db2 on z/OS who want to run that code, change it and check the change, away from the production machine.

## How it runs

COBOL compiles with a patched GnuCOBOL 3.2 in IBM dialect. JCL is interpreted. `EXEC SQL` runs against SQLite through GixSQL, not Db2. VSAM, GDG, DFSORT, IDCAMS and a CICS region are modelled. See [What runs](/harwell/what-runs).

Named for the Harwell Dekatron, the oldest working digital computer.
