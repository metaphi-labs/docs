Harwell is a runtime for z/OS application code. It runs the COBOL programs, JCL, copybooks, BMS maps and Db2 DDL of an existing mainframe application, with no changes to the source. Harwell runs two kinds of workload:

| Workload | What runs | What the report contains |
| --- | --- | --- |
| Batch | JCL jobs: their steps, the programs and utilities those steps call, and the data sets and Db2 tables they read and write | Each job and step, with its return code or abend code, its printed output, and the data sets and tables it left |
| Online | CICS transactions in a region: their programs, BMS maps, files, queues and Db2 access | Each screen the task sent, as the terminal shows it, with each unit of work and each abend |

Batch and online workloads share the same Db2 tables, VSAM files and generation data groups.

You use Harwell to run, change and test mainframe application code without running it on the production system.

## Features

**Runs your code unchanged.** Harwell reads the codebase in its existing layout. A `harwell.toml` file at the codebase root declares the libraries, search orders and Db2 catalog. For details, see [Get started](/harwell/evaluate).

**One report for each run.** Every run returns one JSON report. The report records each job and step, its return code, its output, the screens each transaction sent, and the starting data. For details, see [Run report](/harwell/report).

**Explicit handling of unsupported constructs.** Harwell does not skip what it cannot run. It rejects such a construct by name and gives the reason. When a run reaches a known difference from z/OS behavior, the report names it with its source location. For details, see [Supported features](/harwell/what-runs) and [Known limitations](/harwell/known-limits).

**Repeatable runs.** All dates and times that a program reads come from one run clock. The same input on the same Harwell version gives byte-identical output.

**Expected results.** You can state the data sets, tables and screens that a run must produce. The report then gives a verdict for each one, and names the first record and byte where a data set differs.

**3270 terminal access.** A TN3270 emulator connects to a running CICS region. You can record a terminal session and run it again as a test case.

## How Harwell runs your code

| Component | Implementation |
| --- | --- |
| COBOL | GnuCOBOL 3.2 in IBM dialect, with patches for IBM numeric behavior |
| JCL | Interpreted, including procedures, symbolic parameters, COND and IF/THEN/ELSE |
| Db2 | `EXEC SQL` runs on SQLite through GixSQL, with Db2 13 for z/OS SQLCODEs and decimal rules |
| VSAM, GDG | KSDS, RRDS, alternate indexes and generation data groups |
| Utilities | DFSORT, ICETOOL, IDCAMS, IEBGENER, IEBCOPY and the Db2 utilities |
| CICS | A region with file control, temporary storage, transient data, BMS, program control and interval control |

For the full list, see [Supported features](/harwell/what-runs).

## Versions

This documentation describes Harwell release 0.41.0. Two version identifiers appear in Harwell output:

| Identifier | Example | Description |
| --- | --- | --- |
| Release | `0.41.0` | The Harwell release. |
| Toolchain version | `v1.40` | The engine contract. Every report records it in `toolchain.version`. It changes only when the engine contract changes, so several releases can share one toolchain version. |

To identify the exact engine that produced a report, use `toolchain.engine` and `toolchain.stamp`. For details, see [Report reference](/harwell/report-reference#top-level).
