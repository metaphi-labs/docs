Harwell returns one JSON report for every run. The report records each job and step, its return code, its printed output, the screens that each transaction sent, and the data that the run started from. The success of a job is stated in the report, not in the process exit code. If Harwell rejects a request, the report gives the reason.

## Batch run report

The following example is the report of a one-step job that reads Db2 and writes a data set. It is shortened, and the names are changed.

```json
{
  "report": 1, "mode": "chain", "status": "ok",
  "jobs": [{
    "name": "CRDRENW", "job_id": "JOB00001", "status": "ok", "worst_rc": 0,
    "log": "JOB CRDRENW  [ok]\n  STEP01         CRDRENW    db2       ran           RC=0    ran (DB2); 1 out DD(s)  [cpu=0.030s wall=0.053s peak-rss=147700K]",
    "steps": [{
      "name": "STEP01", "pgm": "CRDRENW", "kind": "db2", "status": "ran", "rc": 0,
      "note": "ran (DB2); 1 out DD(s)",
      "stdout": "CARD RENEWAL - 20260915\n...\nCOMPLETE - EXPIRED 0003 REPLACED 0002 SKIPPED 0001\n",
      "stdout_bytes": 420,
      "dd_dsn": {"CARDOUT": "APP.CARD.MAILING"},
      "dd_lrecl": {"CARDOUT": 90}, "dd_recfm": {"CARDOUT": "FB"},
      "output_bytes": {"CARDOUT": 180}, "output_records": {"CARDOUT": 2},
      "libraries": [{"callee": "CRDGEN", "library": "Progs", "member": "/tmp/unitzip_3jx1xnpj/Progs/CRDGEN.cbl"}],
      "load_module": {"name": "CRDRENW", "library": "Progs", "member": "/tmp/unitzip_3jx1xnpj/Progs/CRDRENW.cbl"},
      "stubbed": [], "neutralized_verbs": {},
      "cpu_s": 0.03, "wall_s": 0.053, "max_rss_kb": 147700
    }],
    "spool": [{"job": "CRDRENW", "job_id": "JOB00001", "step": "STEP01", "dd": "SYSOUT", "records": 9, "bytes": 420}]
  }],
  "start_state": {"source": "unit"},
  "fidelity": {"status": "clean", "neutralized": [], "neutralized_verbs": [], "divergences": [], "deck_warnings": []},
  "toolchain": {"version": "v1.40", "cobc": "3.2.0", "gixpp": "1.0.20b", "dialect": "ibm-fixed",
                "engine": "600da4ee529b", "flags": ["-fixed", "-std=ibm", "-fno-arithmetic-osvs", "-fec=EC-DATA-INCOMPATIBLE"],
                "stamp": "385ba68c3ff240af"},
  "metrics": {"cpu_s": 0.03, "wall_s": 0.053, "max_rss_kb": 147700, "cpu_by_owner": {"program": 0.03}}
}
```

`toolchain.version` is the engine contract, not the Harwell release. For details, see [Versions](/harwell/overview#versions).

A program that does not compile has status `failed`, with the stage and the first error:

```
"stage": "cobc", "first_error": "'WS-TOTAL' is not defined"
```

| Key | Description |
| --- | --- |
| `status` | `ok` when every job ended `ok` or `skipped`; `failed` otherwise |
| `jobs[]` | One per job, in run order: `name`, `status` (`ok`, `failed`, or `blocked` when a job it depends on failed), `steps`, the job log, every spool file |
| `jobs[].steps[]` | One per step reached: `name`, `pgm`, `kind`, `status`, `rc`, `stdout`, `stderr`, bytes and records per DD, the data set behind each DD |
| `jobs[].steps[].termination` | The abend a step ended on: a program check (`S0C7`, `S0CB`, `S0C9`) or an unhandled I/O condition |
| `oracle` | Present when the run supplies an expected end state: `passed`, and a verdict per data set, table and screen |
| `fidelity` | `clean` or `degraded`, with each divergence, stub and CICS command answered without running. See [Divergences](#divergences) |
| `toolchain` | What the run executed on: compiler versions, whether the runtime is the patched one, the exact flags, one digest over all of it |
| `configuration` | Every setting that can change an output byte, with where it came from |
| `start_state` | Where the starting data came from: a snapshot, a kept volume, the site's declared tables and data sets, or empty |
| `metrics` | CPU, wall time and peak memory for the run; the same per step and per job |
| `timeline` | Each phase of the call as a timed span: compiles, links, each step |

For every key, with its type and whether it is always present, see [Report reference](/harwell/report-reference).

## Expected results

If the run supplies the expected output data sets, the report includes a verdict for each one:

```json
"oracle": {"passed": true,
           "datasets": {"PAY.TOTAL": {"verdict": "match", "code": "equal",
                                      "expected_bytes": 20, "actual_bytes": 20}}}
```

If a data set differs, `passed` is `false`, and the entry gives a code such as `bytes_differ` and a description: `PAY.TOTAL: a and b first differ at record 0, byte 12 of the record`.

## Online run report

The following example is the report of a transaction run through 13 screens, with an expected screen for each turn. It is shortened to one screen and two of its fields, and the names are changed.

```json
{
  "mode": "decks", "status": "ok",
  "jobs": [{"name": "CRDMJOB", "status": "ok",
            "steps": [{"name": "STEP01", "pgm": "CRDMNT", "kind": "db2", "status": "ran", "rc": 0,
                       "note": "ran (CICS+DB2); 0 out DD(s)"}]}],
  "cics": {
    "transactions": {"CRDM": "CRDMNT"},
    "screens_in": 13,
    "returns": [{"transid": "CRDM", "commarea": ""}],
    "screens_out": [{
      "map": "CRDM1A", "mapset": "CRDM01", "size": [24, 80],
      "text": [
        " CARD MAINTENANCE (CRDM)                                                        ",
        " ACTION (C/R/U/D) .:                     C                                      ",
        " CARD NUMBER (PAN) :                     4111110000000013                       ",
        "...",
        " MESSAGE ..........:                     CARD CREATED                           "
      ],
      "fields": [
        {"name": "ACTION", "row": 3, "col": 42, "length": 1, "value": "C", "source": "program",
         "attrb": ["NORM", "UNPROT", "IC"], "attr_ebcdic": "80", "color": null, "hilight": null},
        {"name": "MSG", "row": 21, "col": 42, "length": 39, "value": "CARD CREATED", "source": "program",
         "attrb": ["NORM", "PROT"], "attr_ebcdic": "20", "color": null, "hilight": null}
      ],
      "cursor": [3, 42]
    }]
  },
  "oracle": {"passed": true,
             "screens": {"0": {"verdict": "match", "map": "CRDM1A"}, "1": {"verdict": "match", "map": "CRDM1A"}}},
  "fidelity": {"status": "clean"},
  "toolchain": {"version": "v1.40"}
}
```

A run with a CICS region includes `cics`:

| Key | Description |
| --- | --- |
| `cics.screens_out` | Every send painted on its physical map, in order: map, mapset, the text as the terminal shows it, each field with its row, column, length, value and attributes, and the cursor |
| `cics.maps_sent` | Every SEND MAP, in order, with the symbolic map's bytes |
| `cics.text_sent` | Every SEND TEXT |
| `cics.uow` | Every unit-of-work boundary: commit or rollback, at a syncpoint, task end or abend, with the files, queues and SQL it covered |
| `cics.abends` | Each task that abended: transaction, abend code, program, whether its changes were backed out |
| `cics.terminal_waits`, `cics.screens_unread` | Where the screens the run was given and the tasks did not meet |
| `cics.files`, `cics.ts_queues`, `cics.td_queues` | The region's files and queues at the end |
| `cics.transactions` | The program control table |
| `cics.bms` | The mapsets assembled, any rejected with the reason, assembler warnings, and each `SEND MAP`/`RECEIVE MAP` whose program layout does not match the map |

## Divergences

The `fidelity` object records each place where the run did not do what z/OS does:

| Key | Description |
| --- | --- |
| `fidelity.status` | `clean`, or `degraded` if any of the following lists is non-empty |
| `fidelity.divergences` | Each known limitation that the run reached, with its `kind`, job, step, program, data set, member and line |
| `fidelity.neutralized` | Each called program that had no source and was replaced by a stub |
| `fidelity.neutralized_verbs` | Each CICS command that the region answered without running it |

`status` and `fidelity.status` are independent. A run can have `status: failed` and `fidelity.status: clean`. To look up a `kind`, see [Known limitations](/harwell/known-limits).
